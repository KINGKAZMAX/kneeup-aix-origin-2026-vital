## 0. 模块总览（开发者实现清单）

```
web/src/lib/synth/
  rng.ts        // ⑤ 种子策略：hashString + mulberry32 + gaussian
  signals.ts    // ① 三路信号数学模型（纯函数 step 生成器）
  timeline.ts   // ② 180s 演示时间线（分阶段参数表 + 事件点）
  safety.ts     // ④ 安全状态机（SAFE/RISK/OVER + 滞回）
  patients.ts   // ③ 3个虚拟患者档案 + 7天打卡 + 报告要点
  useSession.ts // (可选) React hook：驱动 timeline+signals+safety 输出帧
```

**采样率：10 Hz（dt = 100 ms），可配置 10–20 Hz。** 180s 会话 = 每通道 1800 点 × 3 通道 ≈ 5.4k 点，Recharts `LineChart` 关闭动画（`isAnimationActive={false}`）可直接渲染；实时页只渲染滑动窗口最近 600 点（60s），全量数据留给训练后报告图。

统一数据帧（每 tick 推给患者端）：

```ts
interface SynthFrame {
  t: number;            // 会话秒数 (0–180)
  emg: number;          // sEMG 包络 μV（0–260）
  mdf: number;          // 中值频率可视化代理 Hz（55–95）※合成指标，非实测
  angle: number;        // 屈膝角度 °（0–95）
  pressure: number;     // 关节腔压 kPa（0–30，合成单位）
  state: SafetyState;   // 'SAFE' | 'RISK' | 'OVER'
  riskScore: number;    // 0–1
  compIdx: number;      // 代偿指数 0–1
}
```

## ① 三路信号数学模型

### ①-1 屈膝角度 θ(t)——重复动作周期波形

一屈一伸为一个周期，用「升余弦半波」保证起止平滑、Recharts 曲线好看：

```
θ(t) = A(t) · s(φ) + tremor(t)
s(φ) = 0.5 · (1 − cos(2πφ)),   φ = (t mod T_cycle) / T_cycle
tremor(t) = 0.8 · sin(2π · 0.3 · t)          // 生理颤动代理，恒定小幅
A(t) = A_phase · (1 + 0.03 · n(t))           // n(t)∈[-1,1] 为种子噪声
```

| 参数 | 默认值 | 说明 |
|---|---|---|
| T_cycle | 6.0 s | 3s 屈 + 3s 伸，峰值为 A(t)，起止为 0° |
| A_phase | 见②时间线 | 安全区 65°，风险期递减至 35°，恢复期回升 |
| 噪声幅度 | ±3% | 种子噪声 |
| 量程 | 0–95° | UI 红线画在 90° |

### ①-2 sEMG 包络 E(t)——疲劳上升曲线（激活幅度递增）

负荷形状由角度驱动（屈得越深、激活越高），疲劳因子 f(t)∈[0,1] 使同等动作下幅度递增：

```
L(θ)  = (sin(θ · π/180))^1.2                  // 归一化负荷形状 0–1
E(t)  = E_rest + (E_peak − E_rest) · L(θ) · F(t) + ε_E(t)
F(t)  = 1 + k_f · f(t)                        // 疲劳放大器
ε_E   = 0.05 · E · g1 + 4 · g2                // 5% 乘性 + 4μV 加性高斯噪声
```

疲劳因子一阶动力学（各阶段参数见②）：

```
df/dt = η · u(t) − λ · (1 − f),    u(t) = L(θ)   // 用力越猛积累越快
```

疲劳可视化代理（**合成指标，UI 注明"疲劳代理指标"**）：

```
MDF(t) = 92 − 28 · f(t)      // 92Hz → 64Hz 随疲劳下降
```

| 参数 | 值 | 说明 |
|---|---|---|
| E_rest | 8 μV | 静息基线 |
| E_peak | 120 μV | 无疲劳时深屈膝峰值；f=1 时约 200 μV |
| k_f | 0.6 | 疲劳增益 |
| η（安全/风险/超限/恢复） | 0.010 / 0.028 / 0.020 / 0（λ=0.05） | 40s 内 f≈0.25；80s 时 f≈0.7 |
| f 初值 | 0.05 | 会话开始非零 |
| f 范围 | [0, 1] | clamp |

### ①-3 关节腔压 P(t)——角度相位变化 + 基线漂移

```
P(t) = P_base(t) + K_p · (θ(t)/90) · (1 + c · f(t)) + ε_P(t)
P_base(t) = P0 + d · (t − t_phase_start) + 0.4 · sin(2π · 0.2 · t)   // 0.2Hz 慢波动
```

- `K_p = 14 kPa`：全屈膝的名义压力贡献（65° 时约 +10.1 kPa）。
- `c = 0.5`：疲劳时代偿性共同收缩放大压力（风险期关键项）。
- `d`：基线漂移斜率，分阶段给（安全期 0.015，风险期 0.05 —— 漂移+疲劳共同把峰值推过 22 kPa 超限线）。
- `ε_P`：±0.3 kPa 高斯噪声。

安全/超限参考线（UI 横线）：安全带 <16 kPa；警戒带 16–22；**超限线 22 kPa**。

## ② 训练会话时间线（默认 3 分钟演示脚本）

总长 180s，5 个阶段 + 关键事件点。所有阶段参数按秒线性插值切换（避免跳变）。

| t 区间 | 阶段 | A(t) 幅度 | 疲劳 η/λ | 压力 P0 / d | 状态（预期） |
|---|---|---|---|---|---|
| 0–40s | 安全区 | 65°（每周期 ±3% 抖动） | η=0.010 | 6.0 kPa / 0.015 | SAFE（绿） |
| 40–80s | 代偿风险渐进 | 65°→35° 线性下降（回避深屈） | η=0.028 | 6.0→7.5 kPa / 0.05 | ~t=62s 转 RISK（黄） |
| 80–100s | 超限触发安全状态机 | 35°→30°，OVER 后→5°（暂停） | η=0.020 | 7.5 kPa / 0.05 | ~t=84s 触发 OVER（红）→自动泄气 |
| 100–180s | 恢复 | 30°→60° 缓升（每周期+1.5°） | λ=0.05（疲劳消退） | 6.0 kPa / 0.01 | RISK→SAFE（~t=112s 回绿） |

**事件点（讲稿/演示卡对齐）**：

| 时刻 | 事件 |
|---|---|
| t=40s | 阶段切换：幅度开始下降，疲劳加速 |
| t≈62s | riskScore 首次 ≥0.40 持续 2s → **RISK**，患者端弹纠正提示卡「检测到代偿趋势：建议放慢节奏、减小屈膝幅度」 |
| t≈84s | 峰值压力 ≥22 kPa 持续 1.5s → **OVER**：UI 红灯「已停止加压，立即泄气中，建议暂停训练」 |
| t≈86s | 泄气完成：P 指数衰减（τ=0.4s）至 ~5 kPa，θ 幅度压到 5° |
| t=100s | 恢复阶段开始，用户点击「继续训练」→ 幅度缓升 |
| t≈112s | riskScore ≤0.30 持续 3s → 回 **SAFE** |
| t=178s | 会话收尾：输出 AI 训练报告（本次摘要+进步点+下次建议） |

- 手动模式（/simulator 滑块）：疲劳速度倍率 ×(0.2–3)、腔压基线 ±3 kPa、屈膝幅度 20–90°，直接乘到上述参数上；时间线脚本与手动模式共用同一 `signals.ts`。
- 快速演示档：`timeScale=3`（180s→60s 走完），路演超时保险。

## ③ 患者档案合成数据（3 个虚拟患者）

> 类型定义：`interface CheckInDay { day:1–7; pain:0–10; swelling:0–3; catching:0–3; givingWay:0–3; completionPct:0–100; note:string }`
> AI 摘要仅描述**数据趋势与训练行为**，不做医学判断；文案过禁用词审查。

### P1 · Zhiyuan（Persona 主角）

- 档案：62 岁退休建筑师，左膝半月板**术后**康复场景；钩子「我不想只做病人——我想更聪明地再去爬山」。高依从、稳步向好。
- 7 天打卡：pain `5,5,4,4,3,3,3`；swelling `1,1,1,0,0,0,0`；catching `2,1,1,1,0,0,0`；givingWay 全 `0`；completion `80,85,90,90,95,100,100`%。
- 每日 note 示例：d1「上下楼有点费劲」→ d4「今天走完了 20 分钟」→ d7「膝盖感觉稳了」。
- 报告要点（医生端 AI digest 演示）：「7 天训练完成率 91%，疼痛自评 5→3；屈膝训练幅度 65°→78°；疲劳出现时间从 22s 延后到 45s；无异常打卡信号。建议：维持当前计划，可尝试增加 1 组耐力练习（供参考，非医疗建议）。」

- 档案：45 岁业余跑者，右膝运动后疼痛；依从中等、数据波动，**代偿模式被 AI 识别**（黄灯主角，对应 90 秒闭环里的风险案例）。
- 7 天打卡：pain `4,3,4,5,4,3,3`；swelling `0,1,1,1,0,0,0`；catching `1,1,2,2,1,1,0`；givingWay `0,0,1,1,0,0,0`；completion `100,75,80,60,85,90,95`%。
- 报告要点：「完成率 84% 但 d3–d4 打卡疼痛回升 +2；连续 2 次训练在 60–75s 出现代偿趋势（幅度下降、疲劳代理指标偏高）；AI 已自动下调建议幅度至 55°。建议：维持减量 3 天后再评估。」

### P3 · 淑芬（年长退变倾向，危机转介演示）

- 档案：68 岁，膝关节慢性劳损（退变倾向）；依从偏低，**d4 触发红灯信号**（疼痛骤增+肿胀发热 → 「建议尽快就医」转介演示，对应情报库第2节红线）。
- 7 天打卡：pain `3,3,6,7,4,3,3`；swelling `0,1,2,3,1,0,0`；catching `1,2,2,2,1,1,0`；givingWay `1,1,2,2,1,0,0`；completion `60,50,0,0,40,60,70`%（d4–d5 未训练）。
- 报告要点：「d4 打卡出现红灯信号（疼痛 7 + 肿胀发热），系统已提示『建议尽快就医』；d6 起恢复低强度训练。建议：维持保守幅度 40°，关注打卡信号。」

## ④ 安全状态机定义

复现硬件逻辑（情报库§3：超限→停止加压、立即泄气、提示暂停）。三态 + 滞回防抖。

**输入指标**（每 tick 计算）：

```
compIdx   = clamp(0.6·max(0,(A_ref−A)/A_ref) + 0.4·max(0,(92−MDF)/40), 0, 1)   // 幅度下降+MDF下降
pExcess   = clamp((P − 16) / (22 − 16), 0, 1)                                   // 压力超额归一
riskScore = clamp(0.40·f + 0.35·compIdx + 0.25·pExcess, 0, 1)
```

**状态转换条件**（阈值可 constants 导出，滑块可调）：

| 转换 | 条件 | 说明 |
|---|---|---|
| SAFE→RISK | riskScore ≥ 0.40 持续 ≥ 2.0s | 进入代偿风险 |
| RISK→SAFE | riskScore ≤ 0.30 持续 ≥ 3.0s | 滞回带 0.30–0.40 防来回抖动 |
| RISK→OVER | P ≥ 22 kPa 持续 ≥ 1.5s **或** riskScore ≥ 0.85 持续 ≥ 2s | 超限（压力优先） |
| SAFE→OVER | 同上压力条件 | 安全区直接超限（手动滑块拉爆时） |
| OVER→(暂停挂起) | 立即执行：停止加压 + 泄气（P 指数衰减 τ=0.4s 至 ≤6 kPa），θ 幅度→5° | 硬件行为可视化 |
| (暂停)→SAFE | 用户点击「继续训练」且 P ≤ 8 kPa 持续 ≥ 3s | 恢复期幅度缓升，不允许直接跳回高幅度 |

**每个状态的 UI 信号**：

| 状态 | 灯色 | 患者端文案 | 附加 UI |
|---|---|---|---|
| SAFE | 🟢 绿 `#22c55e` | 「运行正常 · 支撑与压力在安全范围内」 | 无 |
| RISK | 🟡 黄 `#eab308` | 「检测到代偿趋势：建议放慢节奏、减小屈膝幅度」 | 纠正提示卡片（可关闭）；图表上黄色带 |
| OVER | 🔴 红 `#ef4444` | 「压力超限：已停止加压，正在立即泄气。建议暂停训练，稍作休息」 | 全屏轻遮罩 + 按钮「稍作休息」「继续训练」；红色警示带；事件写入报告 |

文案红线自查：以上不含「诊断/治疗/处方/治愈」，全部为操作性动作（停止加压、立即泄气）与建议（建议暂停、建议放慢）。每页保留固定免责声明组件。

## ⑤ 随机种子策略（演示可复现）

**原则：数据路径禁用 `Math.random()` 与 `Date.now()`**；同一种子在任何机器/任何刷新下输出逐点一致（SSR 与客户端也不会 hydration mismatch）。

```ts
// rng.ts —— FNV-1a 哈希 + mulberry32 + Box-Muller 高斯
export function hashString(s: string): number {
  let h = 2166136261 >>> 0;
  for (let i = 0; i < s.length; i++) h = Math.imul(h ^ s.charCodeAt(i), 16777619);
  return h >>> 0;
}
export function mulberry32(seed: number): () => number {
  let a = seed >>> 0;
  return () => {
    a = (a + 0x6d2b79f5) | 0;
    let t = Math.imul(a ^ (a >>> 15), 1 | a);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}
export function makeGauss(rand: () => number): () => number { /* Box-Muller：√(−2ln u)·cos(2πv) */ }
```

**种子命名空间**（`DEMO_SEED = "AIR-FLOW-Knee-AIxOrigin-2026-HK"`）：

| 用途 | 种子串 |
|---|---|
| 信号噪声（每会话） | `knee:demo:${DEMO_SEED}:${sessionId}` |
| 患者 7 天打卡扰动 | `knee:patient:${patientId}:checkin` |
| AI 报告生成随机化（如需） | `knee:patient:${patientId}:report:v${n}` |

- 主演示统一用 `sessionId = "demo-90s"`：路演每次点击「开始」输出**完全相同**的曲线与触发时刻（≈62s 黄、≈84s 红），讲稿可精确对轴。
- 需要新变化时（评委要求"再跑一次看看"）：`sessionId = "demo-90s-v2"`（盐值 +1），行为模式一致、噪声细节不同。
- 测试建议：golden value 断言——`t=10s: θ≈65°, E≈75±8μV, P≈13.5±0.5kPa, state=SAFE`；`t=90s: state=OVER`；快照测试锁住种子行为。
