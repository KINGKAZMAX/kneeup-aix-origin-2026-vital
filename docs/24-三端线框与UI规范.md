## 0. 红线遵循声明（本文档所有文案已自查）

1. **禁用词**：界面文案中绝不出现情报库 §2-1 所列四个禁用词及其任何变体（含近义组合，如"开…方""治…"类表述）。医生端功能一律叫 **「训练计划 / 运动建议」**。提测前用禁用四词做全站 grep（见 §8 自查清单）。
2. **免责声明**：每页固定可见，文案逐字为：
   > 本产品为康复训练辅助软件，非医疗器械，不提供医疗建议，不能替代专业诊疗
3. **危机转介**：红灯信号 → 文案「建议尽快就医」。
4. **数据标注**：每页页脚固定：
   > 本演示全部使用合成数据，无真实患者数据
5. 所有AI产出（建议/摘要/报告）必须挂 `AITag` 组件：「AI 生成 · 仅供参考」。

## 1. 全局信息架构

### 1.1 路由总表

| 路由 | 角色 | 核心任务 | 状态机概要 |
|---|---|---|---|
| `/` | 入口导航页 | 四端入口卡片 + 现场QR码说明 | 静态 |
| `/patient` | 患者端 | 打卡 → AI建议 → 训练 → 报告 | `checkin → suggest → training → report` |
| `/doctor` | 医生端 | 看AI摘要 → 调整计划 → 下发 | `list → digest → editor → confirm → dispatched` |
| `/simulator` | 设备模拟器 | 自动脚本/手动推流 + 三态状态灯 | `idle → safe → comp_risk → over_limit → reset` |
| `/dashboard` | AI数据大屏 | 路演投屏背景，只读 | 静态 + 实时滚动 |

### 1.2 全局布局（所有路由共用 `AppShell`）

```
│    不能替代专业诊疗                                            │
├──────────────────────────────────────────────────────────────┤
│                                                              │

│                                                              │
├──────────────────────────────────────────────────────────────┤

│  本演示全部使用合成数据，无真实患者数据 · AI 生成内容仅供参考     │
└──────────────────────────────────────────────────────────────┘
```

- TopNav 当前路由项：钴蓝 `#4376EB` 文字 + 底部2px钴蓝指示条。
- 演示快捷键（仅demo构建生效）：`1/2/3/4` 切换患者端/医生端/模拟器/大屏，`S` 启动模拟器脚本。
- 断点：现场演示按 **1440×900** 设计；`/dashboard` 额外适配 1920×1080 投屏（内容区锁定16:9栅格）。

### 1.3 三端联动的数据流（一条总线）

```
/doctor 计划下发 ──┐
                  ├──► 共享Store（zustand）+ BroadcastChannel跨Tab同步
/simulator 遥测推流 ─┘         │
                              ▼
              /patient 训练页实时图表 + /dashboard 滚动
```

- `PlanUpdate` 事件：医生端下发 → 患者端顶部横幅「今日计划已更新」。
- `TelemetryFrame` 事件（4Hz）：`{ t, semg(µV), pressure, angle(°), fatigue(0-100), state: safe|comp_risk|over_limit }`。
- 跨Tab失败兜底：同Tab内直接走store；现场演示建议医生端/患者端/模拟器开三个Tab。

## 2. 患者端 `/patient` 逐屏线框

页面内为单页向导式流程，顶部步骤条贯穿四步：

```
① 今日打卡 ● ─── ② AI建议 ○ ─── ③ 训练模式 ○ ─── ④ 训练报告 ○
```

### 2.1 屏A · 今日打卡（step = checkin）

```
┌────────────────────────────────────────────────────────────┐
│ 你好，陈志远（合成患者）                          {今日日期}  │
│ 开始今天的康复训练前，先花30秒记录身体感受                     │
├────────────────────────────────────────────────────────────┤
│ ┌─ 卡片：疼痛程度 ────────────────────────────────────────┐ │
│ │  0 ────────●────────── 10        当前值 [3]（mono大字）  │ │
│ │  无疼痛                        无法忍受                  │ │
│ └─────────────────────────────────────────────────────────┘ │
│ ┌─ 卡片：肿胀 ─────┐  ┌─ 卡片：卡顿 ─────┐  ┌─ 打软腿 ────┐ │
│ │ ○无 ●轻微 ○明显   │  │ ○无 ●有          │  │ ○无 ●有     │ │
│ └──────────────────┘  └─────────────────┘  └─────────────┘ │
│ ┌─ 卡片：补充说明（选填）─────────────────────────────────┐  │
│ │ [ textarea 占位：今天有没有什么特别的感觉？ ]             │  │
│ └─────────────────────────────────────────────────────────┘  │
│                                                             │
│              [ 提交打卡，获取今日AI建议 ]  ← Primary大按钮     │
└────────────────────────────────────────────────────────────┘
```

- 数据：`pain: 0-10` 滑块；`swelling: none|mild|obvious`；`catching: bool`；`givingWay: bool`；`note: string`。
- **红灯规则（前端即时计算）**：`pain ≥ 7` 或 `相对昨日疼痛 +≥3` 或 `swelling = obvious` → 提交后不进训练，改出 **危机转介卡（CrisisCard）**：

```
┌─ ⚠ 红灯信号 ────────────────────────────────────────────┐
│  检测到疼痛明显加重 / 肿胀发热提示。                        │
│  建议尽快就医，今天先不安排训练。                           │
│  [ 今日休息 ]（Primary）   [ 以更低强度继续 ]（Secondary）  │
└─────────────────────────────────────────────────────────┘
```

- 状态流转：`draft → submitted →(红灯?) crisis_branch / ai_loading`。

### 2.2 屏B · AI建议卡（step = suggest）

```
┌────────────────────────────────────────────────────────────┐
│ 步骤条（②高亮）                                             │
├────────────────────────────────────────────────────────────┤
│ ┌─ AI今日训练建议 ──────────────────── [✦ AI生成·仅供参考] ─┐ │
│ │ （ai_loading 时：骨架屏 + 「AI 正在读取你的打卡记录…」闪烁）│ │
│ │                                                        │ │
│ │  今天状态：轻度疼痛（3/10），可以正常训练，               │ │
│ │  建议把强度控制在平时的 80%。                             │ │
│ │                                                        │ │
│ │  今日动作（来自医生「训练计划」+ AI微调）：                │ │
│ │  1. 坐姿伸膝   12次 × 3组   支撑档位 2档                 │ │
│ │  2. 靠墙静蹲   30秒 × 3组   支撑档位 2档                 │ │
│ │  ⚠ 注意点：动作放慢，膝盖不超过脚尖                        │ │
│ │  💬 鼓励语：昨天你多完成了1组，今天稳住节奏就很好。         │ │
│ │                                                        │ │
│ │  [ 开始训练 ]（Primary）   [ 查看医生计划原文 ]（文字链）  │ │
│ └─────────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────┘
```

- 数据来源：医生端已下发的计划（seed或真实下发）+ 打卡数据 → LLM结构化输出（JSON：总评/动作列表/注意点/鼓励语）。**必须准备模板兜底**：LLM超时>3s或失败时使用预生成缓存，保证现场必出结果。
- 状态流转：`ai_loading → ai_ready → start_training`。

### 2.3 屏C · 训练模式（step = training）

布局：左侧数据区（2/3宽）+ 右侧控制区（1/3宽），训练页隐藏步骤条、最大化图表空间。

```
┌──────────────────────────────────────────────────────────────┐
│ 头部条：坐姿伸膝 · 第2组/共3组 · 剩余 08:32   [ 暂停 ] [ 结束 ] │
├──────────────────────────────────────┬───────────────────────┤
│ ┌─ sEMG 疲劳曲线（钴蓝 #4376EB）────┐ │ ┌─ 本次进度 ────────┐ │
│ │  实时折线，60点滚动窗口(15s)       │ │ │  次数  8 / 12     │ │
│ │  绿区(安全) / 黄带(疲劳上升)       │ │ │  组数  2 / 3      │ │
│ │  红带(超限) 半透明色块背景         │ │ │  组间休息 00:20    │ │
│ │  右上角当前值：128 µV（mono）      │ │ ├─ 实时状态灯 ──────┤ │
│ └──────────────────────────────────┘ │ │  ● 安全（绿）      │ │
│ ┌─ 关节腔压（浅蓝 #9DB8F7）─────────┐ │ │  （黄=代偿风险     │ │
│ │  实时折线 + 医生设定的支撑上限虚线  │ │ │    红=已超限）     │ │
│ └──────────────────────────────────┘ │ ├─ 动作要点 ────────┤ │
│ ┌─ 屈膝角度（中性灰 #8B909A）───────┐ │ │ · 放慢速度         │ │
│ │  实时折线 + 目标角度区间背景带      │ │ │ · 膝盖不过脚尖     │ │
│ └──────────────────────────────────┘ │ │ · 呼气发力         │ │
│                                      │ └───────────────────┘ │
├──────────────────────────────────────┴───────────────────────┤
│ [警示卡浮层，从顶部滑入，覆盖在图表上方，10s自动收起或点击关闭]   │
└──────────────────────────────────────────────────────────────┘
```

**安全区间渲染规则（三张图统一）**：
- 绿区：`rgba(47,191,131,0.10)` 背景；黄带 `rgba(240,179,78,0.10)`；红带 `rgba(229,84,75,0.12)`；边界用1px虚线。
- 阈值来自**医生计划**：`支撑范围→腔压上限虚线`、`终止条件→疲劳红线/代偿连击红线/角度下限`（医生端设定 → 患者端安全区间，闭环叙事重点）。

**两张警示卡（WarningCard / HaltCard）**：

```
┌─ ⚡ 代偿风险提示（warning #F0B34E 边框+10%底色）─────────────┐
│ 检测到动作变形迹象：大腿外侧在代偿发力。                       │
│ 纠正提示：放慢速度，让大腿前侧发力更集中。                    │
└─────────────────────────────────────────────────────────────┘
┌─ 🛡 已超限 · 设备已自动保护（danger #E5544B 边框+10%底色）─────┐
│ 已停止加压、立即泄气，请暂停休息。                            │
│ （30秒冷却后）[ 我已休息，继续 ]  [ 结束训练 ]                │
└─────────────────────────────────────────────────────────────┘
```

- 状态机：`countdown(3,2,1) → active ⇄ paused →(comp_risk) warned →(over_limit) halted → resting → completed`。
- 触发源：模拟器推流的 `state` 字段 + 前端本地阈值双保险（无模拟器时也能用合成回放数据演示）。

```
│ ┌ 指标行（4个MetricStat，mono大数字）──────────────────────┐ │
```

- 状态流转：`post_pain → report_loading → report_ready → synced`。

- 状态流转：`reading_digest →(去调整) editor`。

### 3.3 屏C · 计划编辑器（view = editor）

```
┌────────────────────────────────────────────────────────────┐
│ 调整训练计划 · 陈志远            [ ✦ AI建议调整 ]（钴蓝描边钮）│
├────────────────────────────────────────────────────────────┤
│ ┌ 动作块 1：坐姿伸膝 ─────────────────────────── [ 删除 ]──┐ │
│ │ 次数 [12] × 组数 [3]   节奏 [慢起-慢放 3秒]               │ │
│ │ 支撑范围（气囊档位）  1 ────●──── 5   当前 2档            │ │
│ │   ↳ 提示：档位越高支撑越强；上限将同步为患者端腔压安全线     │ │
│ │ 终止条件（患者端自动执行）：                               │ │
│ │   ☑ 疼痛 ≥ [6]/10   ☑ 连续代偿 ≥ [3]次                   │ │
│ │   ☑ 屈膝角度低于 [75]°  ☑ 单次时长上限 [15]分钟           │ │
│ └───────────────────────────────────────────────────────────┘│
│ ┌ 动作块 2：靠墙静蹲（同结构，折叠态）───────────────────────┐│
│ [ + 添加动作 ]（虚线框按钮）                                 │
├────────────────────────────────────────────────────────────┤
│ 生效日期 [今天]   备注 [ 将静蹲组间休息延长10秒 ]（选填）      │
│        [ 预览并下发 ]（Primary，进入3.4）                    │
└────────────────────────────────────────────────────────────┘
```

- 「AI建议调整」点击后：AI依据摘要自动填充草稿改动（如：静蹲次数 3→2、支撑 2→3档），改动项**高亮钴蓝描边**（`#4376EB`），医生可逐项改回——体现"AI建议、医生决定"。
- 四要素与患者端/模拟器的映射（开发者必须实现）：
  - `支撑范围` → 患者端腔压图上限虚线 + 模拟器超限阈值
  - `终止条件·疼痛` → 患者端即时弹窗
  - `终止条件·连续代偿` → 患者端黄区→红区判定
  - `终止条件·角度下限` → 患者端角度图目标区间下界
- 状态流转：`editing →(预览) confirm`。

## 7. 90秒演示路径 · UI走查标注

走查原则：医生端开局（专业视角抓评委）→ 下发（闭环起点）→ 患者端（用户视角）→ 模拟器（技术亮点）→ 报告 → 回医生端（闭环收口）。操作者全程只点 Primary 按钮 + 快捷键切端。

| 秒 | 端/屏 | 操作 | UI焦点（观众看哪） | 口播要点（已过红线） |
|---|---|---|---|---|
| 0-8 | `/doctor` 患者列表 | 点开「陈志远」 | 黄色「风险分级：中」徽章 + ✦AI标记 | 「医生不再逐条看数据，AI先把异常挑出来」 |
| 8-20 | `/doctor` AI摘要 | 读摘要→点「去调整训练计划」 | AI摘要叙述段 + 风险依据 | 「一周变化、疲劳代偿模式、风险分级，三句话说清」 |
| 20-33 | `/doctor` 编辑器→确认 | 点「✦AI建议调整」→「预览并下发」→「确认下发」 | 改动项钴蓝高亮 + 对比表 + 「已下发」 | 「AI给建议，医生拍板——下发立刻同步到家里」 |
| 33-43 | `/patient` 打卡→AI建议 | 快捷填打卡（预置3/10）→提交 | AI建议卡打字机式出现 | 「患者在家打卡，AI结合医生计划给今天建议」 |
| 43-63 | `/patient` 训练 + `/simulator` | `3→4`切模拟器，播「代偿出现」脚本，再切回患者端 | 三张实时图 + 黄色代偿警示卡滑入 | 「护膝数据实时推流，AI识别代偿并给纠正提示」 |
| 63-72 | `/simulator`→`/patient` | 脚本走到T+45s超限 | 红灯脉冲 + 「停止加压·立即泄气·提示暂停」 | 「超限自动保护——支撑恰到好处，不过度」 |
| 72-82 | `/patient` 报告 | 结束训练→10秒疼痛快记→报告 | AI报告卡 + 指标大数字 | 「训练完，AI生成报告，进步点与下次建议」 |
| 82-90 | `/doctor` 患者列表 | 切回医生端 | 「今日新摘要」红点 + 摘要置顶 | 「新的摘要已回到医生面前，一镜闭环完成」 |

**演示可靠性预案**：
- 打卡值、患者数据、医生计划全部**预置seed**；LLM输出预生成缓存兜底（>3s即用缓存）。
- 模拟器脚本固定60s版本（4x速度可压缩到15s）；红灯触发点在T+45s，与讲稿秒数对齐。
- 晚间排练≥3遍（情报库§6），每次用同一份seed重置脚本 `npm run demo:reset`。
