## 一、近两年健康赛道 Hackathon 获奖展示方式复盘

**核心结论：Execution beats idea（执行胜过创意），评委在前90秒就基本打完分。**

1. **时间配比是硬通货**（AngelHack 幕后复盘）：3分钟槽位 = 30s问题+方案一句话 → **90s真正演示（占一半时长）** → 30s技术栈与最难工程点 → 30s下一步/影响。比例比分钟数重要：5分钟槽位延长的是演示和展望，**绝不是开场铺垫**——"更长的setup只给评委更多坐立难安的时间"。
2. **健康AI赛道的评审权重**：Impact + 技术可靠性是第一权重；主题契合度（严格映射challenge statement的约束）单独计分——本赛制即"评委三问过滤"，逐条呼应即可白拿分。Out-Of-Pocket 2025医疗AI hackathon复盘指出：2026年评委的期待已从"接了个大模型"升级为**"有完整工具链的真实集成"**。
3. **"点名你的模型"是2026最大变化**：只说"我们用了LLM/AI"得0分；要说出哪个模型、为什么选它而不是别的、如何检验输出质量。→ 对应本项目：讲DeepSeek/credits的选择理由 + AI摘要的幻觉控制（只基于打卡结构化数据）。
4. **评委巡展/桌面场景**（科学 fair + expo 通用打法）：准备**30-60秒电梯钩子**（评委刚站定时用）+ **2-5分钟展开版**（评委停留时用）两档脚本；互动演示控制在体验顺畅的节奏内，别让评委排队或尴尬等待。
5. **演示失败预案是所有来源的共识第一戒律**：前一晚录一遍干净跑通的演示视频存本地，网络依赖步骤（LLM API、跨Tab同步）全部准备本地fixture替身。wifi和live API必然出事，备份视频是自信的来源。

## 二、Soft Healthcare 双端演示（患者端+医生端）的叙事顺序

**核心结论：跟随一位患者走完全程——患者侧先行，医生端作为"系统响应"切镜，以结果收尾。**

1. 最佳实践案例（ScienceSoft康复软件MVP = 患者App + 医生Web双端；RONDesignLab EHR+；InteliChart患者旅程指南）共同采用**"患者旅程"作叙事脊柱**：pre → during → post，正好映射本项目的打卡 → 训练 → 报告/医生摘要。
2. 切镜顺序的行业范式：**患者痛点场景 → 患者端操作 → 切到临床侧看数据/做出响应 → 回到患者侧看到变化 → 收尾讲结果与下一步**。医生端绝不是第二个"产品介绍"，而是"患者故事里另一位角色"。这与情报库§4的90秒闭环（医生摘要→下发→患者打卡→训练→报告→医生新摘要）完全同构，验证了编排正确。
3. Salesforce演示方法论：先定一个"大问题"（本项目：*"出院后的90天，谁来保证他没偷懒也没硬撑？"*），整个demo就是回答它的过程。DemoBoost叙事法：以动作开场、留悬念（先把疲劳滑块拉到警戒再解释为什么系统拦住了）。
4. 每个功能用"七句话框架"讲：现状→问题→功能→演示→背后→差异→下一步，防止讲解发散。

## 三、暗黑科技风医疗 UI 设计语言（Dribbble/Awwwards 级参考）

**核心结论：2025-26临床监控场景"深色为默认"，neon点缀+极简排版是获奖签名风格；但要控色、要过对比度。**

1. **配色**：深海军蓝/炭黑底（#0A0E1A一类）+ **电光青/teal/荧光绿作生命体征与AI元素点缀**——这是Muzli 2026精选中"cinematic暗黑健康界面"的标配。警报色严格语义化：绿=安全区/黄=代偿风险/红=超限，且全场唯一，不挪作装饰。
2. **控色纪律**：分类色≤6个（Berkeley指南上限6-12，医疗场景取下限），一眼可读优先；采用色盲安全调色板 + WCAG对比度合规（IBM Carbon做法：**先设计深色主题再适配浅色**）。
3. **图表**：实时流数据（sEMG波形/角度曲线）用细线+发光描边，安全区间用半透明色带而非实色块；大数字用mono字体（心率监护仪语言）。
4. **布局**：临床dashboard的铁律是"一眼读完"（Fuselab）——单屏一个主任务，主视觉留一个焦点图表，其余降级为次要卡片。
5. **可对标站点**：OptaPro（暗色运动科技+运动员数据分析，气质最接近）、BetterMe（健康科技Honorable Mention）、Anima Wellness（3D WebGL沉浸健康页）、Awwwards Dark Mode合集、Dribbble "dashboard 2025"搜索流。→ 本项目UI规范（docs/24，电光青+三态色）方向正确，补齐：字号按"3米可读"现场校验、报警红只出现在状态机。

## 四、2-3分钟评委巡展脚本技巧："先演示还是先讲原理？"

**核心结论：既不是先讲原理，也不是纯讲故事——是"30秒微故事钩子 → 立即上demo → 演示中顺带讲硬技术 → 30秒收尾"。**

1. 共识结构：开场用**一个可共情的挫折瞬间**做setup（Liu下山膝痛/"我不想只做病人"），一切demo之前的内容都是铺垫，之后都是payoff（AngelHack故事弧）。原理讲解**嵌在演示进行中**（"你看到的代偿警示，背后是…"），绝不在demo前单开一段讲原理。
2. **"别复述屏幕上可见的东西"**：评委自己会看，把这些秒数花在看不见的工作上——安全状态机、合成数据管道、跨端同步架构。
3. **背转场词，不背稿**：4-5句路标句（"接下来看医生那头""现在故意让他代偿"）比逐字稿省力且不僵硬。
4. **设计一个记忆锚点**（AngelHack："one memorable moment"）：评委散场后能向同事复述的那个瞬间。必须是产品在"当众做动作"，不是装饰动画。→ 本项目最佳候选：**手动把疲劳滑块拉爆 → 红灯"停止加压、立即泄气"**。
5. 语速**刻意放慢**（YC原话：unnaturally slowly）；超时是常见扣分/出局项，桌上放可见倒计时。
6. Q&A必问题清单提前写答案卡：用户是谁/谁付钱/**哪些真哪些mock**/下一步做什么/为什么这个模型；本赛制追加"医疗器械合规件"标准答法（情报库§2-5）。

## 五、KinDex（同济CDI智能康复服）公开展示参考

检索到的事实：KinDex是同济大学的全织物集成智能康复服，**肩部康复场景，按皮肤形变规律对称布设14个织物传感器+纤维导线，核心卖点是检测"代偿动作"**（compensatory movements）；通过2026院校毕业设计作品展（网易可穿戴设备篇）与Instagram帖传播，叙事钩子是"把专业级动作监测从受控临床环境带到日常/home"。

可借鉴的4个展示手法：
1. **具体数字当信任钩子**："14个传感器"比"多传感器阵列"有力。→ 对应本项目："3路信号4Hz实时推流 / 5态安全状态机 / 90秒闭环"。
2. **"代偿识别"作为智能差异点**——与本项目撞点，说明评委认这个概念；演示里要把"识别出代偿"演得可见可懂。
3. **hero叙事：从医院回到家里**——与"让膝康复走出医院、回到家里"同款框架，验证定位语感。
4. **实物/穿戴实拍镇场**：硬件项目靠原型实拍建立可信度。→ 本项目把Arduino原型实拍（PDF P4）+爆炸图（P5）做成桌面易拉宝/平板轮播，弥补"软件demo看不到硬件"的短板。

## 六、可执行清单（10条）

| # | 行动 | 为什么 |
|---|---|---|
| 1 | **90秒闭环按 30s钩子→60-90s实操demo→30s技术→15s收尾 排练，铺垫句砍到一句话** | AngelHack验证的黄金配比：demo占一半时长；评委前90秒定分；更长setup只会失分 |
| 2 | **先患者端30秒微故事（Zhiyuan一句话挫折），立即进demo；原理全部嵌在演示中讲，绝不单开一段讲架构** | 双端健康产品行业范式=跟一位患者走全程，患者侧先行、医生端作"响应"切镜；先讲原理是巡展大忌 |
| 3 | **把"记忆锚点"定在模拟器：手动拉爆疲劳滑块→红灯"停止加压、立即泄气"→回安全态** | 所有获奖复盘都要求一个评委能复述的高光时刻；让产品当众"做动作"，同时暗合临床视角奖的安全叙事 |
| 4 | **讲看不见的，不念屏幕**：代偿识别逻辑、安全状态机、点名DeepSeek及选型理由、合成数据边界 | 评委自己看得见UI；2026新评分点=必须点名具体模型+质量检验方式，只说"AI"得0分 |
| 5 | **所有端满种子数据+快捷键1/2/3/4/S预置，LLM响应预生成缓存，现场零输入零等待** | 评委看到空态=未完成；dead air是巡展头号杀手；AngelHack最终小时清单的硬项 |
| 6 | **QR码落患者端打卡页（手机可真操作），评委扫码打卡→AI建议→大屏同步出现他的数据** | 巡展QR最佳实践=介入式体验而非首页链接；"评委本人成为患者"是把观看者变参与者的最强互动 |
| 7 | **桌面配置：双屏（外屏1920×1080跑/dashboard轮播+主屏走闭环）+桌面倒计时器+免责声明/合成数据声明做成固定视觉元素** | 深色大屏是3秒路过辨识度；合规可见是评审硬门槛，把红线做成设计语言反而显专业；倒计时防超时扣分 |
| 8 | **暗黑UI补三件事：报警三色语义唯一化、主字号过"3米可读"现场实测、图表用发光细线+半透明安全区色带** | 2025-26临床监控深色默认+neon点缀是获奖语言；控色≤6与色盲安全是医疗UI合规审美底线 |
| 9 | **前一晚录干净跑通版视频存本地+离线fixture替身（LLM/跨Tab同步断网兜底），现场排练≥3遍且对外人讲一遍** | wifi与API必挂律：备份是每个来源都排第一的戒律；对陌生人排练能暴露评委真实提问 |
| 10 | **打印Arduino原型实拍+爆炸图做桌面展卡（KinDex式"实物镇场"），并备Q&A答数卡（谁用/谁付/真假数据/下一步/合规件答法）** | 软件demo看不到硬件，实物图补可信度；Q&A必问题提前写好答案，医疗器械问题用§2-5标准答法不慌 |
