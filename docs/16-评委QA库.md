## Q1. Soft Healthcare边界：「你们又是sEMG又是风险分级，怎么保证不越界成医疗器械？」

**变体问法**：「风险分级算不算诊断？」「你们其实想做医疗设备吧，只是现在不说？」

**高分回答框架**：
1. **一句话定性**：主Demo是纯软件闭环——健康信息理解+行为支持+依从陪伴，正是赛道定义的Soft Healthcare（非临床支持）。
2. **三条边界线**（主动划线，不等评委划）：
   - 输出端：AI只产出「训练建议/计划组织」，不产出诊断结论；「风险分级」= 训练安全提示（继续/减量/暂停+建议就医），不是临床判断。
   - 决策权：计划由医生端人工确认后下发，AI只做摘要与草稿，医生是唯一决策者。
   - 呈现端：全站无「诊断/治疗/处方/治愈」词汇+显著免责声明+红灯信号自动转介「建议尽快就医」。
3. **硬件切割**：硬件是背景愿景，不在本Demo功能内；演示中的sEMG/腔压/角度全部来自模拟器推流，是数据流逻辑演示，不测量任何真实人体。
4. **合规姿态收口**：未来商业化若涉及医疗用途，会走正式注册路径评估——这正是我们不宣称医疗用途的原因。（情报库§2标准答法）

**避坑**：不说「AI能识别损伤/判断病情」；不把风险分级说成「评估」；被追问注册标准时不硬扛，回到「所以主Demo严格停在软件闭环」。

## Q2. AI在哪：「把AI拿掉，产品还剩什么？」（评委三问②）

**变体问法**：「这不就是打卡表单+ChatGPT写总结？」「API谁都能调，你的壁垒呢？」

**高分回答框架**：
1. **直接答「去掉AI失去什么」**（三层，每层对应演示里具体一帧）：
   - 理解层：多模态打卡输入→AI结构化为**个性化**当日训练建议；固定表单做不到千人千面。
   - 摘要层：医生面对连续多维时序数据，AI digest把一周数据压缩为「变化趋势+疲劳代偿模式+风险提示」——医生看摘要、不看原始曲线，这是**流程重组**，不是文案生成。
   - 交互层：训练中实时代偿识别与纠正提示，由数据流驱动，非预设文案。
2. **回应wrapper质疑**（用2025投资圈话语）：判断厚薄wrapper的标准是是否有私有资产——我们的闭环每走一圈沉淀纵向个人数据（打卡→建议→反馈→调整），加上医患双端工作流嵌入与信任/合规层；模型可以换，数据回路和工作流换不掉。
3. **收口**：去掉AI，产品退化为「问卷+图表库」——AI实质改变的是理解/摘要/流程组织，正是赛制AI门槛要求的「实质改变」。

**避坑**：不罗列技术栈（LLM API型号）；不说「我们的AI很智能」；一定要落到演示画面的具体对比（如医生端：原始曲线 vs AI摘要）。

## Q3. 数据可信度：「全是合成数据，这个演示到底证明了什么？你们有真实用户吗？」

**高分回答框架**：
1. **主动承认边界**（不等评委戳）：合成数据证明的是**产品逻辑与工作流成立**，不证明临床效果——这两件事我们分得很清。
2. **合成数据的三点价值**：
   - 合规：赛道只允许合成/公开脱敏/模拟数据，我们严格遵守（页脚标注可见）。
   - 可控演示：能稳定复现代偿、超限、红灯转介等关键场景，真实数据无法安全演示。
   - 面向真实：模拟器接口即未来硬件数据接口，安全状态机按真实接入设计，不是为演示特设。
3. **真实验证路线图**（给路径不给假数据）：公开脱敏数据集回放 → 小样本真实佩戴测试 → 团队内试点征集。
4. **诚信加分项**（若被问项目来历）：概念源于赛前研究MENISCUS SHIELD（硬件），Web三端+AI层为比赛期间新做，git log为证。

**避坑**：绝不暗示有任何真实患者数据；不引用PDF中未复核数字（膝压力3-5倍体重/护具降30%风险/病因42-28-19-11——情报库标注待核实，一律不用）；被问真实用户：「赛前0用户，这正是我们在找第一批种子的原因。」

## Q4. 商业路径：「谁付钱？患者自费？保险？医院？企业？」

**高分回答框架**（行业背景：Pear Therapeutics倒闭证明「只有报销故事没有收入模型」是DTx头号死因；Hinge/Sword活下来靠B2B2C雇主/保单付费）：
1. **先说当下**：本阶段不收费，任务是验证闭环价值，不回避支付难题但也不假装已解决。
2. **分层付费逻辑**（框架，不报价格）：
   - 医院/诊所（近期最顺）：帮医生管理出院患者居家依从的工具，机构为「随访效率+患者不离院」付费——HEP软件按医生席位收费已是成熟模式。
   - 患者自费（中期）：康复是长周期高频场景，自费逻辑=省去反复跑院的时间成本；香港私症/自费康复市场存在。
   - 雇主/保险（远期）：肌肉骨骼是职场缺勤与医疗支出主因之一，雇主付费+按效果付费模式已有头部先例——**明确说这需要真实效果数据之后才走**。
3. **地域顺序**：先香港（数码港生态、自费+私症结构）→ 再大湾区。
4. **表态收口**：我们不靠「未来进医保」讲故事——这个行业的教训恰恰是只有报销叙事的公司活不下来。

**避坑**：现场不报任何定价数字；不说「保险/医保会覆盖」；不把单一付费方说成唯一答案。

## Q5. 竞品差异：「Physitrack有11万clinician、几万个动作，你们凭什么？」

**变体问法**：「Hinge Health都上市了，你的空间在哪？」

**高分回答框架**（行业背景：Physitrack=动作库+HEP分发工具，强分发；研究显示数字干预对依从的提升多集中在前8-12周，长期回落）：
1. **先承认**：HEP工具赛道成熟，动作库规模不是我们的战场，我们不装。
2. **差异三层**：
   - 输入差异：Physitrack们知道「患者做没做」，不知道「做得对不对」——我们引入sEMG/角度/腔压数据流（演示中来自模拟器），补**质量维度**。
   - 产出差异：竞品医生端产出=动作清单+打卡列表；我们医生端产出=AI异常摘要+一键计划调整——医生的工作对象不同。
   - 阶段差异（诚实牌）：他们是成熟公司，我们是验证「质量数据+AI闭环」假设的原型。
3. **一句话定位**：不做更大的动作库，做「居家康复质量的可视化与医患闭环」。
4. 若被问Hinge/Sword：他们验证了付费方愿为MSK买单（对我们是利好），我们切入的是他们未覆盖的居家训练**质量监测**环节。

**避坑**：不贬低竞品（Physitrack有RCT背书）；不声称功能全面超越；差异只讲质量维度，不扯「我们更便宜」。

## Q6. 医生端：「有医生会用吗？你访谈过医生吗？」

**高分回答框架**（行业背景：医生采纳的决定因素=不新增工作流负担；EHR负担已是倦怠主因，工具减负才被采纳）：
1. **诚实交代现状**：本阶段未做正式医生访谈（按真实情况说）；设计依据是公开文献中的康复随访痛点——居家依从不可见、逐条看数据没时间。
2. **设计原则**：医生端唯一目标=**30秒看懂一周**——AI digest给摘要而非原始曲线，调整计划一次点击下发；「不给医生新增一个屏幕，而是替医生看掉一屏幕数据」。
3. **现场转化**：邀请提问评委扮演医生，走90秒闭环亲自体验（把质疑变成演示机会——这是最强回应）。
4. **验证路线**：下一步访谈清单（框架）：随访耗时基线 / AI摘要可信度 / 误报容忍度 / 愿意付费的场景。
5. 若冲着Clinician's Choice奖问循证：训练动作与安全区间逻辑引用公开指南框架，风险分级可解释、可追溯（按实际材料说，不夸大）。

**避坑**：绝不编「访谈了X位医生」；不说「医生肯定会用」；用「减负」作为医生端一切设计的验收标准。

## Q7. 依从性：「康复App 30天留存普遍很差，你怎么让62岁的Zhiyuan第8周还在打卡？」

**高分回答框架**（行业背景：实证研究显示数字干预的依从提升多在前8-12周，之后回落——懂行投资人的杀手题）：
1. **先承认**：依从性衰减是全行业实证问题，我们不声称自己例外。
2. **产品侧机制**（讲机制，不编效果数字）：
   - 打卡门槛压到最低（症状打卡+训练记录，分钟级）。
   - 闭环反馈：打卡当天下发可见的计划调整——患者感知「有人在看」，这是纯HEP工具给不了的。
   - 医生端介入=真人连接，依从从「患者自觉」变成「医患共同责任」——医生看得到，才管得了。
   - 进步报告+代偿纠正=即时正反馈。
3. **衡量姿态**：未来试点第一指标=周留存/打卡连续性，不是下载量。

**避坑**：不做「我们的依从率会提高X%」式无依据承诺。

## Q8. 硬件愿景：「气囊+sEMG+泄压安全，你们做得出来吗？量产呢？」

**高分回答框架**：
1. **证据先行**：不是纸面愿景——赛前已有Arduino功能原型实拍（sEMG电极/气泵/继电器）、站立vs屈膝波形对比、爆炸图与充放气原理（作品集P4/P5，可投屏）。
2. **分层诚实**：
   - 已验证：传感采集与充放气执行回路原理跑通；安全状态机逻辑（超限→停止加压→立即泄压→提示暂停）。
   - 未验证（主动列明）：长时间佩戴可靠性、传感器标定、量产成本、生物相容性——这是硬件化里程碑序列的后续项。
3. **软硬同构**：模拟器里的安全状态机就是硬件安全逻辑的软件镜像——软件先行沉淀数据结构与控制逻辑，硬件按「监测先行、支撑后置」推进。
4. **团队配置**：用户=工业设计背景，硬件原型在本队能力圈内；算法与供应链是未来补强项。
5. 合规问题引回Q1框架：硬件若宣称医疗用途将走注册评估——所以它现在只是背景愿景。

**避坑**：不承诺量产时间表与成本数字；不说「医疗级」；不把硬件说成本届交付物。

## Q9. 隐私合规：「健康数据上云？LLM API看得到症状？内地香港跨境怎么办？」

**高分回答框架**：
1. **当下事实**：演示全部合成数据，零真实可识别健康数据——赛制红线我们主动做到（页脚标注可见）。

## Q10. 团队：「你们5个人、工业设计背景，凭什么做医疗？」

## Q11. 为什么现在/为什么膝盖？（Lan Lu·长寿视角主攻题）

**高分回答框架**：
1. **需求侧**：膝部问题伴随衰老极普遍（术后/退变/运动损伤三大人群）；术后早出院→居家康复缺口扩大，居家依从无人管。
2. **供给侧**：康复专业人力稀缺，软件是切入居家场景成本最低的方式。
3. **为什么是现在**：LLM让个性化陪伴与医生端摘要的成本骤降；传感方案成本下降让「训练质量数据」进入家庭成为可能。
4. **长寿叙事收口**（面向Lan Lu）：老年人在家安全训练、有支撑地活动=健康寿命延长链条里的一环；从膝到更多关节、更多慢病行为支持——软硬结合的长寿科技路径。

**避坑**：患病率/老人比例等数字情报库标注待核实——一律用「普遍/高发」定性，不报具体百分比。

## Q12. 比赛之后：「从demo到第一批用户，路径是什么？」

**高分回答框架**（三步，不画五年曲线）：
1. **验证**：小样本真实佩戴测试+医生访谈，把合成场景换成真实数据结构。
2. **种子**：1-2家康复科/诊所试点，按医生席位工具模式（对应Q4近期付费方）。
3. **迭代决策**：用留存与摘要质量数据决定走向「机构工具」还是「患者自费」——数据说话再选主航道。
4. **资源请求具体化**：需要临床顾问与试点机构引荐（点名Cyberport生态/评委网络）。

**避坑**：不画营收曲线；不说「先免费圈用户再变现」这类含糊话。
