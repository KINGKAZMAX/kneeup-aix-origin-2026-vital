# AI 观察层实现规格（拟开发，非已实现能力）

本规格是在现有 USB 只读基线上的开发建议，不是原项目文档的改写。长期目标仍是自适应主动助力；本轮只做可追溯 AI 观察，不把它称为已完成 Physical AI 执行闭环。

## 1. 数据摘要：程序计算，不让模型编数字

复用 `window.AirflowLive.device` 的 `sample`、`gpio`、`ended`、`change` 和 snapshot。重复 telemetry seq 不增加样本；AI 请求以窗口 + generation + 来源标识归属。sampleAge 与完整帧 age 都要检查，不能因新状态帧不断到达而把旧样本说成新肌电。

可确定性计算：窗口起止、有效新样本数、最小/最大/均值、采样间隔、最新样本年龄；有已上报 A5 才摘要指令变化。有用户明确标注基线时才计算数字相对变化。

不得计算或宣称：肌力、疲劳、坡度、步态类别、左右差异、助力百分比、EMG 医学频谱/RMS 指标。旧协议的数字只是稀疏滤波结果；不要把摘要做成临床特征或补成高频波形。没有证明接触质量的输入时，不声称电极接触“良好”。

设置公开可调的工程门槛：最少有效样本、窗口时长、最长样本年龄、最小请求间隔。阈值仅用于软件数据充分性检查，不是医学标准。数据不足时直接显示原因，不触发模型解释。

## 2. 建议接口与结构

以下路径与字段是待实现规格，不是现有 API；可以合理微调但保持语义和测试。

- `GET /api/ai/status`：只返回 configured、model 标签、能力模式，不返回任何密钥。
- `POST /api/ai/analyze`：接收经过大小/类型/数值范围校验的摘要；不要接受前端任意覆盖模型系统提示词或上游 URL。
- 手动“分析当前窗口”作为默认；无需为每个点调用模型。

输入包括：`requestId`、`generation`、`source`、`protocol`、`windowId`、`windowStartMs`、`windowEndMs`、`sampleCount`、`lastSampleAgeMs`、`statistics`、`threshold`、`thresholdSource`、可选 `a5Summary`、可选 `baseline`。

来源：保留现有 `serial` 与 `simulated`；若新增回放则显式 `replay`。`thresholdSource` 区分 `firmware_reported` / `source_reference` / `none`。未上报字段保持 null/缺失，不设假默认测量值。

输出至少包括：

| 字段 | 生成方 / 含义 |
|---|---|
| requestId / windowId / generation / source | 程序绑定，不能由模型自报改写 |
| mode | 服务端设置 `model` / `rule_fallback` / `unavailable`，不能由模型自封 |
| model / generatedAt / latencyMs | 服务端真实调用元信息；没有调用不能写成功 |
| observation | 对输入数字与规则的观察；不能扩展为医学判断 |
| evidence | 对本次输入字段的引用；程序验证路径和对应值 |
| suggestionCode | 有限枚举：collect_more_data / label_baseline / review_setup / continue_observing / no_recommendation |
| explanation | 建议与证据之间的解释，不是硬件命令 |
| limitations | 如没有角度、压力、校准、只读观察等 |
| appliedToHardware | 程序固定 false；本轮没有控制路径 |

严格区分模型生成字段和服务端可信元数据。拒绝未知动作、外带指令、无效 JSON、超长文本、非有限数字、不存在的证据或与输入不符的数值引用。输出以文本节点渲染，不执行模型返回 HTML/JavaScript。schema 合法不等于内容已经正确，仍需证据校验与可见限制。

展示“为何触发”时，只能解释已知固件规则和可用日志；旧协议只能展示参考比较。AI 后来生成的解释不是此前气囊响应的原因，事件时间线必须分别记录输入发生时间和 AI 生成时间。

## 3. 本机服务与凭证隔离

现有运行时无依赖；优先保留 Python 本地启动习惯，是否引入轻量依赖由实现需要决定并记录。供应商与接口未知，不固定模型名称或假定任意服务兼容某一 API。

建议环境变量：`AIRFLOW_AI_BASE_URL`、`AIRFLOW_AI_MODEL`、`AIRFLOW_AI_API_KEY`。只提供空模板；不要写入示例真密钥，不从 Codex 配置等其他位置自动抓取密钥。若支持明确的本地无鉴权模型，作为单独模式配置，不能把空 key 默认指向任意网络服务。

模型请求只能到本项目服务端配置的地址；前端无权指定上游 URL。设请求超时、并发上限、请求体大小和调用间隔，限制重试，不形成无限循环。错误返回脱敏；不要向页面泄露上游认证头或原始异常详情。

**当前 serve.py 是通用项目根目录静态服务。添加 .env 前必须改造静态服务：**白名单仅公开确需的 HTML/CSS/JS/图片；禁止目录列表、点文件、路径穿越、.git/.env/私有日志与源资料下载，测试编码后的绕过路径。服务只绑定 loopback，验证 Host/Origin，POST 需同源校验/CSRF 防护，不开放 `*` CORS。

即便本地服务，外部模型仍是数据外发。默认关闭，操作者明确选择并同意后才能发摘要；明确列出字段。能在本地摘要就不上传原始流、视频、身份或长期健康信息。撤销启用时中止待发请求，不再发新数据。

## 4. UI 呈现

保留实时肌电、固件规则与 A5 卡片。新增 AI 区而非另造整套页面：

- 状态：未配置 / 待授权 / 数据不足 / 分析中 / 模型分析 / 规则降级 / 过期。
- 输入：来源、窗口、样本数、是否有真实基线；原始摘要可展开查看。
- 输出：观察、有限下一步建议、数据依据、不能判断什么。
- 可追溯：模型/模式、生成时刻、延迟、对应 windowId；“未应用到硬件”。

不得默认显示一段预写“轻辅助策略”，再把它装作模型输出。默认占位写“等待数据/模型未配置”。不要用虚构置信度或助力百分比美化。

连串口失败、换源、重连、固件 boot、超过新样本年龄门槛、撤销模型授权时应使当前 AI 结果失效；历史结果可保留为历史，不继续作为当前建议。模型晚回包不能污染新的 generation/source/window。用 AbortController/请求 token 等实现并测试。

失网时 USB 曲线继续；模型错误明确显示失败原因类别及规则摘要标签。当前演示输入来自 simulated 时即便实际模型成功，也必须显示“模型分析 · 合成输入”。

## 5. 记录与测试

新增 AI history 到完整会话 JSON，保留原样本字段与 source。记录 request/window/generation、输入摘要、验证后的结果和 mode；不记录密钥或身份数据。不把同一条 AI 建议假装成多个真实测量事件。

最少测试：

1. legacy 与 telemetry 字段缺失、重复 seq、旧样本新状态帧、负数和无效值。
2. 数据不足/无基线时不编造结论；source 变化和重启后旧回复丢弃。
3. 未配置、未授权、超时、断网、401/429/5xx、非法 JSON、未知建议、证据不符、超长文本。
4. mode 由服务端决定；mock 结果和规则输出不能被标成真实模型成功。
5. AI 请求不阻塞图表、不新增串口 writer；页面切换无重复订阅；结束记录不是停泵。
6. 模型文本转义；环境文件/目录遍历/编码路径/错误日志不暴露秘密；非同源请求拒绝。
7. AI 与实测/模拟/回放的来源在 UI 与导出中一致。

将测试结果分为：单元测试、mock 接口、浏览器、真实提供方调用、USB 实板。缺失任一项就明确未验证；不能沿用上一版报告中的通过数来声称新版本已通过。
