### 原固件不能漏掉的细节

A0 单路输入，滤波后与 66.0 比较；达到阈值后 A5=LOW，并等待 4 秒，随后还有 1 秒等待，下一轮开头才写 HIGH。因此不能写成“准确 4 秒充气”，不能写成“持续 500 Hz 肌电”。LOW/HIGH 与继电器、泵、阀的动作映射未完整核实。不能从一次低电平跳变推断一次动作或有效助力。

## 3. 本轮目标：把 AI 放进真实数据观察链，而不是装饰卡片

以下为**建议开发范围，尚未实现**：

```text
EMG → Arduino → USB → 浏览器数据流 → 主界面/会话记录
        └→ 固件规则 → A5 → 原有气动执行（物理状态待现场核对）

浏览器已有数据流
  → 去重/时间与来源校验
  → 当前窗口的数值摘要 + 可选人工标注校准
  → 本机服务端代理
  → 配置的真实模型
  → 结构与证据字段校验
  → AI 观察建议 / 根据哪些数据 / 不能判断什么
  → 时间线 + 会话 JSON

AI 输出 ─×→ 串口写入或气动控制（本轮不实现）
```

**这不是已经完成产品愿景中的“AI 判断需要多少力并调节气囊”。** 保留未来的策略/执行接口设计，但本轮不要偷偷添加自动控制，也不要把文本建议讲成实物控制。

AI 的价值展示落在“把本次输入、规则和记录解释为可追溯的观察与下一步数据采集建议”。若只有确定性阈值比较，就明确显示规则解释；若用户要更进一步的 AI 物理控制，另行核实执行条件和协议后再立项。

## 5. 任务优先级与验收

### P0 — 保留并核查真实输入

先确认基线能启动并复跑现有测试；界面断连、旧协议缺项、重复 seq、演示来源维持正确。缺实物可以继续写代码，但将现场验收列为待办。不要重复重造已存在的 Web Serial。

### P1 — 真实模型的最小观察链

按 `docs/AI_INTEGRATION_SPEC.md` 完成窗口摘要、后端代理、真实模型适配器、程序校验、AI 卡片。先提供手动“分析当前窗口”，而非连续自动调用；手动触发仍需模型配置和外发授权。没有 key/网络时可显示规则摘要，但不得冒充模型结果。

验收：能追溯每次分析的输入窗口、来源、模型调用状态、依据、局限和生成时间；业务结果不具备设备执行权限。

### P2 — 路演与记录

一屏显示信号、固件规则、控制器报告、AI 观察及事件；增加 AI 结果到完整会话 JSON。既有 CSV 采样数据兼容，不把一条 AI 结果复制成每个采样点的实测属性。概念首页可以保留但继续标为示例。

验收：离线/规则/模拟/真实模型清楚区分；发生重连、换源、板子重启后旧 AI 结果失效；没有模型回复也不阻塞 USB 曲线。

### P3 — 可选的有限个体化展示

时间允许才加入“人工明确标注的基线窗口”对照；仅描述本次数字相对该窗口的变化。没有采集基线就不写“高于个人基线”。不把差异当作疲劳、力量不足或临床结论，不生成助力百分比，不自动改阈值。
