# 给现场队友：AIR-FLOW-Knee+ USB + AI 观察版

本版保留原前端和视觉，不需要 npm。交付者手上没有设备；本版没有真实 USB/气动/穿戴验收，也没有真实模型 API 验收。已通过的软件测试使用合成数据、模拟串口或模型替身。

## 启动（无设备也可检查页面）

解压后进入项目目录，用 Python 3.9+：

```bash
python3 serve.py --no-browser
```

Windows 可用 `py -3 serve.py --no-browser`，或双击 `start.bat`。电脑 Chrome/Edge 打开 `http://localhost:8000/?view=hardware`。端口占用用 `--port 8001` 并访问对应端口。不要使用通用静态服务器：它不提供 AI 代理且可能暴露配置。

## 现场操作顺序

1. **先在无设备状态检查页面。** 应显示无数据、AI 未连接；不会自动生成波形。
2. **没有设备时**可点“显式开启合成演示”，等至少 4 秒。这仅验证软件演示，标签与导出必须保留“合成”。
3. **接实物前**停止合成演示，由硬件负责人断开气泵外部电源、核对设备状态与实物停止/泄压方式。先不用更换固件，不在穿戴承重状态下初次联调。
4. 关闭 Arduino 串口监视器/绘图器，USB 数据线连接同一台电脑，点“连接 Arduino USB”。打开串口可能导致 UNO 复位；波特率 115200。
5. 核对协议：原版数字应显示滤波值，A5/RAW 未上报，66 是源码参考值；v1 JSON 才有上报阈值/A5。A5 不代表气压或实际助力。触发后较长采样间隔符合原程序，不是持续 500 Hz。
6. 点“开始记录”，收集至少 5 个新样本，窗口跨度至少 4 秒（原固件可能要等更久）。新状态帧不增加样本数。
7. 队友按 README 配置已有模型账号到本机 `.env`，重启 `serve.py`，点“重新检查模型配置”。核对服务/模型与发送字段，再勾选外发授权。**密钥不填网页、不放 URL，不随压缩包转发。**
8. 点“分析当前窗口”。观察页面显示输入、模型观察、建议、引用依据、限制、模型/时间/状态。“本次模型结果对应的固定输入窗口”可核对精确请求。若输入为合成数据，即使真实模型成功仍应标“真实模型 + 合成输入”。
9. 若未配置、401/429/网络错误或输出不合法，展示“规则解释 / AI 未连接”。曲线仍可用，不把失败讲成 AI 成功。可撤销勾选或停止来源验证旧结果失效。
10. 结束网页记录，导出 CSV、完整会话 JSON，必要时单独导出 AI 历史。确认 JSON 的 `source`、`aiHistory[].input`、`mode`、`result` 和时间对应正确。**结束记录/断开 USB/关闭网页都不是物理急停。**气动恢复与执行验证由硬件负责人另行决定，本版不提供控制按钮。

## 路演说法

产品长期定位：AI Adaptive Mobility Assist System / Active Aging / Mobility Longevity / Assist, not replace。

本次交付：现有 USB 数据流上的可追溯 AI 观察与建议。AI 文本没有发送到设备，不自动调阈值，不控制气泵；还没有完成 AI 物理执行闭环。

现场若只跑了合成输入，讲“合成输入演示”；如果模型未接通，讲“规则解释”。不得展示为实测上楼、疲劳、坡度或助力百分比结论。
