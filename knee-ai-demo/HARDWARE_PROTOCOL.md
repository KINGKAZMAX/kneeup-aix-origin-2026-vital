# AIR-FLOW USB 协议与继续开发说明

## 接线边界

现有程序的输入是 A0，外部控制输出是 A5，串口 115200。本文不是新的接线图。继电器触发极性、常开/常闭触点、泵/阀供电、失电状态与泄压方式没有从现有材料完整核实，不能按此文推断。

## Transport

USB CDC/USB-to-serial → Web Serial；115200、8 数据位、1 停止位、无校验、无流控。每条消息以 LF 结束，CRLF 也接受。每行最多 1024 字符，超长行丢弃到下一个换行。浏览器只读，不调用 `writable`、`getWriter()` 或 `setSignals()`。

## Legacy

```text
12.34
-5.67
```

唯一含义是所提供程序打印的滤波输出。数值不是百分比或已标定的物理单位。缺少 A5、采样时间戳、原始值与压力。页面中的 66.0 是原文件参考阈值，并非回读当前设备配置。

## v1 telemetry

以下是协议示例，不是实测记录：

```json
{"v":1,"type":"telemetry","t_ms":6000,"sample_ms":2000,"seq":2,"raw":512,"emg":70.0000,"threshold":66.00,"a5":"LOW","phase":"rest"}
```

| 字段 | 定义 |
|---|---|
| v / type | 固定 1 / telemetry |
| t_ms | 此帧开始组装时的 MCU millis() |
| sample_ms | 此帧引用样本的 MCU 时间 |
| seq | 只有新 analogRead + Filter 时才递增；状态帧可复用 |
| raw | A0 ADC 读数，UNO 协议范围 0–1023 |
| emg | 与原 Filter 相同的输出，不赋予物理单位 |
| threshold | 固件实际用于比较的阈值 |
| a5 | 固件最后写入 A5 的 HIGH / LOW；不是电流/压力/电机反馈 |
| phase | idle / trigger_hold / rest，程序阶段，不是气囊状态 |

新 seq 才追加曲线和采样记录。相同 seq 的新帧可更新 A5、样本年龄和事件，但不会冒充新肌电采样。将 `t_ms - sample_ms` 按无符号 32 位计算，以处理 millis() 回绕。

启动标记：

```json
{"v":1,"type":"boot","fw":"airflow-observer-v1"}
```

收到启动标记或检测到新数据流时，当前记录结束，实时缓存清空。USB 打开不是身份认证；“实测”仅表示从串口接收到协议数据。

## 前端接入位置

`serial-protocol.js` 是纯函数解析器。`serial-device.js` 发出 `sample`（新样本）、`gpio`（已观察的指令电平变化）、`ended`（数据源结束/重启）、`change`（界面状态更新）。`live-ui.js` 消费这些事件。

未来若接入角度/压力，先由硬件实际测量并定义字段、单位、时间戳及有效性，再更新解析器和 UI。缺失值保持 null/未上报，不用演示值回填。

## 这版故意没有的功能

没有网页急停、远程启动、充气按钮、支撑百分比下发、AI 控制接口、500 Hz 重写、自动阈值优化。增加控制需另行定义可靠执行状态、失联处理、独立停止与物理输出测试，不是在现有模拟滑块上加一个 write()。
